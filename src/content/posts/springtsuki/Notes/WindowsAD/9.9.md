### 2.1.3 dcdiag 巡检

```powershell
dcdiag /e /q /c         # /e 全林 /c 全套 /q 只报错,输出最节省
dcdiag /test:replications
dcdiag /test:connectivity
```

核心看有没有 PASS 以外的行。一般跑 dcdiag 全量会比较慢,巡检可直接 /e /c,或 先 /replsummary 再按需 dcdiag 更高效。

关于高位端口，也可以在这个列表中看到。它指的是 AD 复制和 RPC 通信时使用的那一段端口范围，这在配置防火墙时经常会遇到。

当域控之间需要进行复制、身份验证或其他 RPC 通信时，它们会通过 TCP 135 端口建立连接，然后实际的数据传输会通过动态分配的高位端口进行。

在需要排查问题时，可以在域控上使用以下命令查看当前活动的 RPC 连接：

```powershell
netstat -an | findstr 49152
```

## 4. netsh trace 抓包

netsh trace 是 Windows 内置的网络诊断与跟踪工具。它能捕获网络数据包和系统事件，并生成详细的日志。

它最常用的场景就是抓包。核心流程是“开始捕获”和“停止捕获”两步：

### 4.1 开始捕获网络流量

```cmd
netsh trace start capture=yes
```

如果需要更精细的控制，可以加上一些常用参数：
```cmd
capture=yes # 开始捕获网络流量
tracefile=路径 # 指定生成的 .etl 文件的保存路径和名称
maxsize=数值 # 设置单个日志文件的最大大小（MB），超过会循环覆盖。
persistent=yes # 即使重启电脑，捕获任务也会在重启后继续运行。
```

### 4.2 停止捕获并生成报告

当问题复现后，在命令提示符中执行 netsh trace stop。系统会停止捕获，并开始合并和生成两个文件：

.etl 文件：原始数据文件。

.cab 文件：包含一个 HTML 格式的摘要报告和更详细的数据。

可以直接打开 .cab 文件中的 HTML 报告，可以快速了解网络活动的整体状况。.etl 文件可以用 netsh trace convert 命令转换为 CSV、XML 或文本格式，便于深入分析。


## 5. 软件的批量下发

在此之前，首先需要知道一个叫 `NETLOGON` 的玩意儿。NETLOGON 是每个域控上自动创建的一个共享文件夹(SMB 共享),域内所有计算机和用户都能访问它,主要用来存放"登录/启动脚本"和分发文件。

它对应服务器上的真实路径是: `C:\Windows\SYSVOL\sysvol\<domain>\scripts`

共享名就是 NETLOGON,访问路径: `\\<DC>\NETLOGON`

NETLOGON 不是独立目录,它是 SYSVOL 的一个共享视图。会自动复制到所有 DC。所以后续只需要把需要批量下发的软件安装包（MSI文件）与静默安装脚本置入即可。

这里我们以7zip为例子，写一个软件的静默安装脚本：

```bat
@echo off
REM ============================================
REM  Install.bat - 通过 GPO 启动脚本批量安装软件
REM  用法: 放到 \\<域>\NETLOGON\ 下,由 GPO 启动脚本调用
REM ============================================

REM --- 可修改的配置区 ---
set "SOFTWARE_UNC=\\QYNET-CORE01\NETLOGON\7z2408-x64.msi"
set "LOG_FILE=C:\Windows\Temp\software_install.log"
set "INSTALL_CHECK=C:\Program Files\7-Zip\7zFM.exe"
REM ----------------------

REM 若已安装,直接退出(避免每次开机重装)
if exist "%INSTALL_CHECK%" (
    echo [%date% %time%] Already installed, skipping. >> "%LOG_FILE%"
    exit /b 0
)

REM 检查网络共享是否可达(共享没通就别白试)
if not exist "%SOFTWARE_UNC%" (
    echo [%date% %time%] ERROR: Cannot access %SOFTWARE_UNC% >> "%LOG_FILE%"
    exit /b 1
)

echo [%date% %time%] Starting installation... >> "%LOG_FILE%"

REM 静默安装: /qn 无界面 /norestart 不重启 /l*v 详细日志
msiexec /i "%SOFTWARE_UNC%" /qn /norestart /l*v "%LOG_FILE%.msi"

REM 记录退出码
set "RC=%errorlevel%"
echo [%date% %time%] msiexec exit code: %RC% >> "%LOG_FILE%"

if %RC%==0 (
    echo [%date% %time%] SUCCESS >> "%LOG_FILE%"
) else (
    echo [%date% %time%] FAILED with code %RC% >> "%LOG_FILE%"
)

exit /b %RC%
```

而后，在 GPO 上挂在此脚本用于批量下发：

```
计算机配置 → 策略 → Windows 设置 → 脚本(启动/关机)
```

最后等待作用域中的终端重启或关机，GPO 下发成功后便会在后台静默安装此程序！非常好用！

## 6. A记录 与 SPN记录的 故障排查

那么在了解故障排查的步骤与工具之前，需要先了解什么是 A记录，什么是 SPN记录，他们的作用范围在哪。

`A记录`其实较为简单，它的作用是让域名找到对应的 IP地址，简言之就是 DNS解析记录。

`SPN记录`较为复杂，它的作用是`服务声明标识`，就是需要证明"这个服务属于它"。

```
客户端要访问服务
   ↓
第1步:DNS 查 A 记录 → "web01.qy.net = 192.168.254.10"  ← 找到机器
   ↓
第2步:同机器上跑着很多服务,要访问哪个?用什么身份?
       → 这就轮到 Kerberos/SPN 出场              ← 证明服务身份
```
