# 一、用户与账户

## <div align = "center">Get-ADUser部分</div>

## 1.1 查询用户的基本信息

```powershell
# 查单个用户的基本信息
Get-ADUser -Identity qianyue -Properties *

# 以下仅节选部分输出
DistinguishedName : CN=浅月,OU=User,OU=Admin,OU=Organization,DC=qy,DC=net
Enabled           : True
GivenName         : 月
Name              : 浅月
ObjectClass       : user
ObjectGUID        : a050d085-d8dd-4065-903b-452e9fbb7a75
SamAccountName    : qianyue
SID               : S-1-5-21-2772337105-4098782075-1994570761-1116
Surname           : 浅
UserPrincipalName : qianyue@qy.net
```

这里可以看到很多数据，让我们一个个来分析：

| 属性 | 含义 | 值 |
|---|---|---|
| DistinguishedName | 用户在 Active Directory 中的唯一辨识名称，包含完整的组织单位路径 | `CN=浅月,OU=User,OU=Admin,OU=Organization,DC=qy,DC=net` |
| Enabled | 用户账户是否启用，`True` 表示启用，`False` 表示禁用 | `True` |
| GivenName | 用户的名字或名 | `月` |
| Name | AD 对象名称，通常对应 DistinguishedName 中的 CN 部分 | `浅月` |
| ObjectClass | AD 对象类型，`user` 表示这是一个用户对象 | `user` |
| ObjectGUID | AD 为该对象分配的全局唯一标识符，即使用户改名也通常保持不变 | `a050d085-d8dd-4065-903b-452e9fbb7a75` |
| SamAccountName | 用户登录名，主要用于兼容旧版 Windows/NT 域登录 | `qianyue` |
| SID | Windows 安全标识符，用于唯一标识用户并进行权限判断 | `S-1-5-21-2772337105-4098782075-1994570761-1116` |
| Surname | 用户的姓 | `浅` |
| UserPrincipalName | 用户主体名称，常用的现代域登录格式，通常类似电子邮箱地址 | `qianyue@qy.net` |

## 1.2 查询符合 Filter 参数的用户

顺带学习 Filter 参数的用法。

```powershell
# 查所有启用的用户
Get-ADUser -Filter 'Enabled -eq $true'

# 按名字模糊查
Get-ADUser -Filter 'Name -like "*浅月*"'
```

`-Filter` 后面是一个筛选表达式，通常由“属性、比较运算符和值”组成。`-eq` 表示精确相等；`-like` 表示按照通配符匹配，其中 `*` 代表任意数量的字符。

需要注意，`-like` 只会检查表达式中明确指定的属性。例如 `Name -like "*浅月*"` 只会检查 `Name`，不会自动检查其他属性。

## 1.3 使用 Properties 提供需要额外返回的属性

```powershell
# 推荐：直接查询密码永不过期的用户
Search-ADAccount -PasswordNeverExpires -UsersOnly

# 进阶：通过 userAccountControl 位标志查询
Get-ADUser -Filter 'userAccountControl -band 0x10000' -Properties userAccountControl

# 示例一条：
DistinguishedName  : CN=浅月,OU=User,OU=Admin,OU=Organization,DC=qy,DC=net
Enabled            : True
GivenName          : 月
Name               : 浅月
ObjectClass        : user
ObjectGUID         : a050d085-d8dd-4065-903b-452e9fbb7a75
SamAccountName     : qianyue
SID                : S-1-5-21-2772337105-4098782075-1994570761-1116
Surname            : 浅
userAccountControl : 66048
UserPrincipalName  : qianyue@qy.net
```

`-Properties` 用来指定 `Get-ADUser` 需要额外查询并返回哪些用户属性，`-Filter` 用来筛选用户，两者通常配合使用。例如上述命令通过 `-Filter` 判断 `userAccountControl` 中的密码永不过期标志，并通过 `-Properties` 返回该属性。

`userAccountControl` 是由多个状态位组合而成的数值。示例中的 `66048` 不只代表单一状态，因此需要通过位运算判断其中是否包含指定标志。

## 1.4 配合管道与 Select-Object 来筛选需要的对象

```powershell
# 查询指定 OU 下的所有用户，并仅返回 Name
Get-ADUser -SearchBase "OU=User,OU=Admin,OU=Organization,DC=qy,DC=net" -Filter * |
    Select-Object Name

Name
----
浅月
```

## <div align = "center">Search-ADAccount部分</div>

## 1.5 根据账户状态进行查询

```powershell
# 查锁定中的账户
Search-ADAccount -LockedOut -UsersOnly

# 查密码已过期的账户
Search-ADAccount -PasswordExpired -UsersOnly

# 查已禁用的账户
Search-ADAccount -AccountDisabled -UsersOnly

# 查超过 90 天未登录的用户
Search-ADAccount -AccountInactive -TimeSpan 90.00:00:00 -UsersOnly
```

`Search-ADAccount` 用于按照账户状态进行搜索。如果不指定 `-UsersOnly` 或 `-ComputersOnly`，结果中可能同时包含用户账户和计算机账户。

常见的返回属性包括：

| 属性 | 含义 |
|---|---|
| AccountExpirationDate | 账户过期时间 |
| DistinguishedName | 对象在 AD 中的完整路径 |
| Enabled | 账户是否启用 |
| LastLogonDate | 最近一次登录时间 |
| LockedOut | 账户是否被锁定 |
| Name | 对象名称 |
| ObjectClass | 对象类型，例如 user 或 computer |
| ObjectGUID | 对象的全局唯一标识符 |
| PasswordExpired | 密码是否已经过期 |
| PasswordNeverExpires | 密码是否永不过期 |
| SamAccountName | 旧式 Windows 登录名 |
| SID | 安全标识符 |
| UserPrincipalName | 用户主体名称，例如 qianyue@qy.net |

## 1.6 对帐户执行修改的操作

```powershell
# 启用/禁用账户
Enable-ADAccount -Identity qianyue
Disable-ADAccount -Identity qianyue

# 解锁账户
Unlock-ADAccount -Identity qianyue

# 重置密码
$newPassword = Read-Host "请输入新密码" -AsSecureString
Set-ADAccountPassword -Identity qianyue -Reset -NewPassword $newPassword

# 取消密码永不过期
Set-ADUser -Identity qianyue -PasswordNeverExpires $false

# 强制下次登录改密码
Set-ADUser -Identity qianyue -ChangePasswordAtLogon $true

# 移动用户到另一个 OU
Get-ADUser -Identity qianyue |
    Move-ADObject -TargetPath "OU=NewOU,DC=qy,DC=net"
```

密码不应该以明文形式直接写入脚本或命令历史，因此这里使用 `Read-Host -AsSecureString` 安全地读取密码。管理员重置密码时，需要给 `Set-ADAccountPassword` 添加 `-Reset` 参数。

在移动、禁用等可能影响用户登录的操作前，可以先使用 `-WhatIf` 预览将要执行的操作：

```powershell
Get-ADUser -Identity qianyue |
    Move-ADObject -TargetPath "OU=NewOU,DC=qy,DC=net" -WhatIf
```

另外，设置“下次登录必须修改密码”前，应确保已经取消“密码永不过期”：

```powershell
Set-ADUser -Identity qianyue -PasswordNeverExpires $false
Set-ADUser -Identity qianyue -ChangePasswordAtLogon $true
```

## 1.7 修改用户的常用属性

除了账户状态，还可以使用 `Set-ADUser` 修改显示名称、部门、职位和描述等属性：

```powershell
Set-ADUser -Identity qianyue `
    -DisplayName "浅月" `
    -Department "IT" `
    -Title "系统管理员" `
    -Description "AD 测试账户"
```

修改完成后，可以重新查询并通过 `Select-Object` 查看结果：

```powershell
Get-ADUser -Identity qianyue `
    -Properties DisplayName,Department,Title,Description |
    Select-Object SamAccountName,DisplayName,Department,Title,Description
```

常见的用户资料属性如下：

| 属性 | 含义 |
|---|---|
| DisplayName | 用户的显示名称，常用于管理界面和通讯簿 |
| Department | 用户所在部门 |
| Title | 用户的职位 |
| Description | 用户对象的说明信息 |
| Office | 用户所在办公室 |
| EmailAddress | 用户的电子邮件地址 |
| Manager | 用户的直属负责人 |

## 1.8 设置账户过期时间

对于临时账户，可以设置明确的过期时间：

```powershell
# 设置账户过期时间
Set-ADAccountExpiration -Identity qianyue -DateTime "2026-12-31 23:59:59"

# 取消账户过期时间
Clear-ADAccountExpiration -Identity qianyue
```

查询账户过期时间：

```powershell
Get-ADUser -Identity qianyue -Properties AccountExpirationDate |
    Select-Object Name,Enabled,AccountExpirationDate
```

## 1.9 管理用户的组成员关系

AD 中的权限通常通过组进行分配，因此组成员关系也是用户管理的重要部分。

```powershell
# 将用户添加到组
Add-ADGroupMember -Identity "Domain Admins" -Members qianyue

# 查看用户所属的组
Get-ADPrincipalGroupMembership -Identity qianyue |
    Select-Object Name,GroupScope,GroupCategory

# 将用户从组中移除
Remove-ADGroupMember -Identity "Domain Admins" -Members qianyue -Confirm
```

`Domain Admins` 是高权限组，上述命令只适合在实验环境中练习。生产环境中应遵循最小权限原则，并在修改前确认操作对象。

## 1.10 创建新的用户账户

可以使用 `New-ADUser` 创建用户，并同时设置初始密码、UPN 和所在 OU：

```powershell
$password = Read-Host "请输入初始密码" -AsSecureString

New-ADUser `
    -Name "浅月" `
    -GivenName "月" `
    -Surname "浅" `
    -SamAccountName "qianyue" `
    -UserPrincipalName "qianyue@qy.net" `
    -Path "OU=User,OU=Admin,OU=Organization,DC=qy,DC=net" `
    -AccountPassword $password `
    -Enabled $true `
    -ChangePasswordAtLogon $true
```

创建后可以立即进行验证：

```powershell
Get-ADUser -Identity qianyue -Properties DisplayName,Created |
    Select-Object Name,SamAccountName,Enabled,Created
```

## 1.11 用户无法登录的排查流程

当用户反馈无法登录时，可以依次检查账户是否启用、是否被锁定、密码是否过期以及账户本身是否过期。

```powershell
# 获取账户主要状态
Get-ADUser -Identity qianyue `
    -Properties LockedOut,PasswordExpired,PasswordNeverExpires,AccountExpirationDate,LastLogonDate |
    Select-Object Name,Enabled,LockedOut,PasswordExpired,PasswordNeverExpires,AccountExpirationDate,LastLogonDate
```

可以按照以下顺序进行判断：

1. 检查 `Enabled` 是否为 `True`。
2. 检查 `LockedOut` 是否为 `True`。
3. 检查 `PasswordExpired` 是否为 `True`。
4. 检查 `AccountExpirationDate` 是否已经超过当前时间。
5. 检查用户对象所在 OU 和所属组是否正确。
6. 根据问题执行启用、解锁或重置密码操作。
7. 再次运行查询命令，确认账户已经恢复正常状态。

例如，对锁定账户执行解锁并验证：

```powershell
Unlock-ADAccount -Identity qianyue

Get-ADUser -Identity qianyue -Properties LockedOut |
    Select-Object Name,Enabled,LockedOut
```

需要注意，`LastLogonDate` 通常根据可复制的 `lastLogonTimestamp` 转换而来，适合判断长期未使用的账户，但不适合用作精确到分钟的登录审计记录。

## 2.2 理解组作用域与组类型

`GroupScope` 与 `GroupCategory` 是权限排查中的高频字段：

| 字段 | 取值 | 可以包含的常见成员 | 可以在哪里授权 |
|---|---|---|---|
| GroupScope | `DomainLocal` | 任意受信任域中的账户和全局组，以及本林中的通用组 | 仅当前组所在域 |
| GroupScope | `Global` | 同一域中的账户和全局组 | 本林或受信任域中的资源 |
| GroupScope | `Universal` | 本林任意域中的账户、全局组和通用组 | 本林或受信任林中的资源 |
| GroupCategory | `Security` | 安全主体，可以加入 ACL | 可以用于权限分配，也可以用于邮件分发 |
| GroupCategory | `Distribution` | 仅用于逻辑分组或邮件分发 | 不能用于 ACL 权限分配 |

如果用户已经加入某个组却仍然没有权限，应先检查该组是不是 `Distribution` 通讯组。通讯组不是安全主体，不参与 ACL 访问判定。

```powershell
Get-ADGroup -Identity "QYNET-Admin" |
    Select-Object Name,GroupScope,GroupCategory

Name        GroupScope GroupCategory
----        ---------- -------------
QYNET-Admin Global     Security
```

在多域环境中，通常使用 **AGDLP** 或 **AGUDLP** 模型规划权限：

```text
AGDLP  ：账户（A）→ 全局组（G）→ 域本地组（DL）→ 权限（P）
AGUDLP ：账户（A）→ 全局组（G）→ 通用组（U）→ 域本地组（DL）→ 权限（P）
```

这种方式可以把“人员归属”和“资源权限”分开管理，减少直接向用户账户分配权限的情况。

## 2.3 创建、修改与删除组

创建一个全局安全组：

```powershell
New-ADGroup `
    -Name "GG-IT-Admins" `
    -SamAccountName "GG-IT-Admins" `
    -GroupScope Global `
    -GroupCategory Security `
    -Path "OU=Group,OU=Organization,DC=qy,DC=net" `
    -Description "IT 管理员账户组"
```

执行成功时默认不返回内容，可以立即查询验证：

```powershell
Get-ADGroup -Identity "GG-IT-Admins"

DistinguishedName : CN=GG-IT-Admins,OU=Group,OU=Organization,DC=qy,DC=net
GroupCategory     : Security
GroupScope        : Global
Name              : GG-IT-Admins
ObjectClass       : group
SamAccountName    : GG-IT-Admins
```

修改组的描述信息：

```powershell
Set-ADGroup `
    -Identity "GG-IT-Admins" `
    -Description "用于管理 IT 系统的安全组"
```

执行成功时默认不返回内容，验证结果如下：

```powershell
Get-ADGroup -Identity "GG-IT-Admins" -Properties Description |
    Select-Object Name,Description

Name         Description
----         -----------
GG-IT-Admins 用于管理 IT 系统的安全组
```

修改组对象的名称：

```powershell
Get-ADGroup -Identity "GG-IT-Admins" |
    Rename-ADObject -NewName "GG-System-Admins"
```

执行成功时默认不返回内容。再次查询时，CN 已经发生变化：

```powershell
Get-ADGroup -Identity "GG-IT-Admins" |
    Select-Object Name,SamAccountName,DistinguishedName

Name             SamAccountName DistinguishedName
----             -------------- -----------------
GG-System-Admins GG-IT-Admins   CN=GG-System-Admins,OU=Group,OU=Organization,DC=qy,DC=net
```

`Rename-ADObject` 修改的是对象的 CN；如果还需要修改 `SamAccountName`，应另外使用 `Set-ADGroup`：

```powershell
Set-ADGroup -Identity "GG-System-Admins" -SamAccountName "GG-System-Admins"
```

执行成功时默认不返回内容。可使用以下命令同时验证 CN 与 `SamAccountName`：

```powershell
Get-ADGroup -Identity "GG-System-Admins" |
    Select-Object Name,SamAccountName

Name             SamAccountName
----             --------------
GG-System-Admins GG-System-Admins
```

删除组属于高风险操作，建议先使用 `-WhatIf` 确认目标：

```powershell
Remove-ADGroup -Identity "GG-System-Admins" -WhatIf

What if: Performing the operation "Remove" on target "CN=GG-System-Admins,OU=Group,OU=Organization,DC=qy,DC=net".
```

```powershell
# 确认无误后再执行，并保留确认提示
Remove-ADGroup -Identity "GG-System-Admins" -Confirm

Confirm
Are you sure you want to perform this action?
[Y] Yes  [A] Yes to All  [N] No  [L] No to All  [S] Suspend  [?] Help: Y

# 输入 Y 后执行删除，成功时不会再返回对象
```

## 2.4 查询组成员

```powershell
# 查询组的直接成员
Get-ADGroupMember -Identity "QYNET-Admin"

name              : 浅月
objectClass       : user
SamAccountName    : qianyue
```

```powershell
# 整理常用字段
Get-ADGroupMember -Identity "QYNET-Admin" |
    Select-Object Name,SamAccountName,ObjectClass,DistinguishedName

Name SamAccountName ObjectClass DistinguishedName
---- -------------- ----------- -----------------
浅月 qianyue        user        CN=浅月,OU=User,OU=Admin,OU=Organization,DC=qy,DC=net
```

```powershell
# 只查询直接成员中的用户对象
Get-ADGroupMember -Identity "QYNET-Admin" |
    Where-Object ObjectClass -eq "user"

distinguishedName : CN=浅月,OU=User,OU=Admin,OU=Organization,DC=qy,DC=net

```

如果组中包含嵌套组，可以使用 `-Recursive` 继续展开：

```powershell
Get-ADGroupMember -Identity "QYNET-Admin" -Recursive |
    Select-Object Name,SamAccountName,ObjectClass

Name SamAccountName ObjectClass
---- -------------- -----------
浅月 qianyue        user
```

需要注意，`-Recursive` 返回的是递归展开后的末端成员，不适合用来还原完整的嵌套层级。如果需要检查“哪个组嵌套了哪个组”，仍应先查看直接成员，并逐层查询其中的组对象。

统计组中递归展开后的用户数量：

```powershell
$members = Get-ADGroupMember -Identity "QYNET-Admin" -Recursive

$members |
    Where-Object ObjectClass -eq "user" |
    Measure-Object

Count    : 1
Average  :
Sum      :
Maximum  :
Minimum  :
Property :
```

## 2.5 查询用户属于哪些组

使用 `Get-ADPrincipalGroupMembership` 查询用户的组成员关系：

```powershell
Get-ADPrincipalGroupMembership -Identity qianyue |
    Select-Object Name,GroupScope,GroupCategory,DistinguishedName

Name        GroupScope GroupCategory DistinguishedName
----        ---------- ------------- -----------------
Domain Users Global    Security      CN=Domain Users,CN=Users,DC=qy,DC=net
QYNET-Admin Global     Security      CN=QYNET-Admin,OU=Group,OU=Organization,DC=qy,DC=net
```

只查看安全组：

```powershell
Get-ADPrincipalGroupMembership -Identity qianyue |
    Where-Object GroupCategory -eq "Security" |
    Select-Object Name,GroupScope

Name         GroupScope
----         ----------
Domain Users Global
QYNET-Admin  Global
```

如果只想查看用户对象 `memberOf` 属性中记录的直接组成员关系，可以使用：

```powershell
(Get-ADUser -Identity qianyue -Properties MemberOf).MemberOf |
    ForEach-Object { Get-ADGroup -Identity $_ } |
    Select-Object Name,GroupScope,GroupCategory

Name        GroupScope GroupCategory
----        ---------- -------------
QYNET-Admin Global     Security
```

`memberOf` 只记录直接成员关系，而且通常不包含用户的主组，例如默认的 `Domain Users`。排查有效组成员关系时，更适合使用 `Get-ADPrincipalGroupMembership`，并结合登录会话中的访问令牌进行确认。

## 2.6 添加与移除组成员

```powershell

Add-ADGroupMember `
```

## 2.7 查询空组与统计成员数量

查询没有任何直接成员的组：

```powershell
Get-ADGroup -Filter * -Properties Members |
    Where-Object { -not $_.Members } |
    Select-Object Name,GroupScope,GroupCategory,DistinguishedName

Name                GroupScope  GroupCategory DistinguishedName
----                ----------  ------------- -----------------
WSUS Reporters      DomainLocal Security      CN=WSUS Reporters,CN=Users,DC=qy,DC=net
WSUS Administrators DomainLocal Security      CN=WSUS Administrators,CN=Users,DC=qy,DC=net
DHCP Users          DomainLocal Security      CN=DHCP Users,CN=Users,DC=qy,DC=net
```

查询每个组的直接成员数量：

```powershell
Get-ADGroup -Filter * -Properties Members |
    Select-Object Name,GroupScope,GroupCategory,
        @{Name="DirectMemberCount";Expression={ @($_.Members).Count }} |
    Sort-Object DirectMemberCount -Descending

Name                    GroupScope  GroupCategory DirectMemberCount
----                    ----------  ------------- -----------------
Exchange Servers        Universal  Security                      2
QYNET-Admin             Global     Security                      1
Organization Management Universal  Security                      1
WSUS Reporters          DomainLocal Security                      0
```

需要注意，`Members` 属性和上面的统计结果只包含直接成员，不会自动计算嵌套组中的用户。如果对所有组逐一执行递归查询，会对域控制器产生更多查询压力，生产环境中应尽量限制 OU 和组的范围。

## 2.8 转换组作用域与类型

使用 `Set-ADGroup` 可以修改组作用域：

```powershell
# 将全局组转换为通用组
Set-ADGroup -Identity "GG-IT-Admins" -GroupScope Universal

# 修改组类型
Set-ADGroup -Identity "Mail-IT" -GroupCategory Security
```

两条命令执行成功时默认不返回内容，可以分别查询验证：

```powershell
Get-ADGroup -Identity "GG-IT-Admins" |
    Select-Object Name,GroupScope,GroupCategory

Get-ADGroup -Identity "Mail-IT" |
    Select-Object Name,GroupScope,GroupCategory

Name         GroupScope GroupCategory
----         ---------- -------------
GG-IT-Admins Universal  Security

Name    GroupScope GroupCategory
----    ---------- -------------
Mail-IT Universal  Security
```

组作用域不能任意转换，常见约束如下：

| 转换方向 | 主要约束 |
|---|---|
| Global → Universal | 当前全局组不能是另一个全局组的成员 |
| DomainLocal → Universal | 当前域本地组不能包含其他域本地组，并且成员必须符合通用组的成员规则 |
| Universal → Global | 成员必须符合全局组规则，即只能包含本域账户和本域全局组，不能包含通用组 |
| Universal → DomainLocal | 当前通用组不能处于不允许转换的通用组或跨域域本地组嵌套关系中 |
| Global ↔ DomainLocal | 不能直接互转，需要先转换成 Universal，再转换为目标作用域 |

早期的 Windows 2000 Mixed 模式不支持 Universal 安全组，也不允许组作用域转换；这不是“林功能级别低于 2003”的限制。现代 AD 环境通常不会再使用该模式，但转换前仍然必须检查成员和嵌套关系。

组类型从 `Distribution` 改成 `Security` 后可能立即影响权限判定；从 `Security` 改成 `Distribution` 后，ACL 中引用该组的授权将不再生效，因此修改前应先检查使用范围。

## 2.10 “已经加入组但仍然没有权限”的排查流程

当用户已经加入组但仍然无法访问资源时，可以按照以下顺序排查：

1. 检查目标组的 `GroupCategory` 是否为 `Security`。
2. 检查用户是否是该组的直接成员或递归成员。
3. 检查嵌套组的作用域和成员规则是否合法。
4. 检查用户当前登录令牌中是否已经包含该组。
5. 检查资源 ACL 是否真正向该组授予了权限。
6. 检查是否存在优先级更高的显式拒绝权限。
7. 检查域控制器复制是否已经完成。

首先检查组本身：

```powershell
Get-ADGroup -Identity "QYNET-Admin" |
    Select-Object Name,GroupScope,GroupCategory,DistinguishedName

Name        GroupScope GroupCategory DistinguishedName
----        ---------- ------------- -----------------
QYNET-Admin Global     Security      CN=QYNET-Admin,OU=Group,OU=Organization,DC=qy,DC=net
```

然后检查用户是否位于递归成员列表中：

```powershell
Get-ADGroupMember -Identity "QYNET-Admin" -Recursive |
    Where-Object SamAccountName -eq "qianyue"

distinguishedName : CN=浅月,OU=User,OU=Admin,OU=Organization,DC=qy,DC=net
name              : 浅月
objectClass       : user
SamAccountName    : qianyue
```

在用户实际登录的计算机上检查当前访问令牌：

```powershell
whoami /groups

GROUP INFORMATION
-----------------

Group Name             Type             SID                                           Attributes
====================== ================ ============================================= ==================================================
QYNET\QYNET-Admin      Group            S-1-5-21-...                                  Mandatory group, Enabled by default, Enabled group
QYNET\Domain Users     Group            S-1-5-21-...-513                              Mandatory group, Enabled by default, Enabled group
```

组成员关系发生变化后，已经存在的登录会话不会自动获得新的访问令牌。最可靠的验证方式是让用户注销并重新登录；某些 Kerberos 场景也可以执行 `klist purge` 后重新访问资源，但现有 SMB 会话等连接仍可能继续使用旧状态。

检查文件或目录 ACL：

```powershell
Get-Acl -Path "\\server\share\folder" |
    Select-Object -ExpandProperty Access |
    Where-Object IdentityReference -like "*GG-IT-Admins*"

FileSystemRights  : Modify, Synchronize
AccessControlType : Allow
IdentityReference : QYNET\GG-IT-Admins
IsInherited       : True
InheritanceFlags  : ContainerInherit, ObjectInherit
PropagationFlags  : None
```

最后检查 AD 复制状态：

```powershell
repadmin /replsummary

Source DSA          largest delta    fails/total %%   error
DC01                       05m:12s    0 /   5    0

Destination DSA     largest delta    fails/total %%   error
DC01                       05m:12s    0 /   5    0
```

如果不同命令连接到了不同域控制器，也可以使用 `-Server` 指定同一台 DC 进行对比：

```powershell
Get-ADGroupMember `
    -Identity "QYNET-Admin" `
    -Recursive `
    -Server "dc01.qy.net"

distinguishedName : CN=浅月,OU=User,OU=Admin,OU=Organization,DC=qy,DC=net
name              : 浅月
objectClass       : user
SamAccountName    : qianyue
```

排查权限问题时，需要同时区分三件事：AD 中保存的组成员关系、用户登录时生成的访问令牌，以及目标资源上的实际 ACL。只确认其中一项，并不能证明权限已经完整生效。
